# Text speech-form analysis — Qwen3-8B

Находит в русской расшифровке фрагменты монолога, диалога, полилога и
неопределённые фрагменты. Отдельно отмечает тип общения: доклад, интервью,
дискуссия, вопросы и ответы и т. д. Аудио не используется.

## Запуск в Windows PowerShell

```powershell
cd D:\Projects\hack-18881e5e-team-main\02_Speaker_Diarization_and_Identification
.\run.ps1
# Один файл:
.\run.ps1 -InputFile ..\01_Speech_Transcription_Module\outputs\01_audio\01_audio.json
```

Если политика PowerShell запрещает запуск локальных скриптов, разовый запуск:
`powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1`.

Без аргументов обрабатываются JSON из `01_Speech_Transcription_Module/outputs/*/`.
JSON должен содержать `segments` с `text`, необязательными `id`, `start`, `end`.
Также поддерживаются текстовые файлы UTF-8. Для TXT символьные границы сохраняются,
временные метки внутри текста остаются текстом, новые времена не выдумываются.

Результаты: `outputs/<имя>.speech_forms.json` и читаемый Markdown рядом.
Для файлов с одинаковым именем используйте разные `--output-dir` при вызове Python.

## Модель и сервер

Официальный Qwen3-8B-GGUF, квантование Q4_K_M, файл 5.03 GB. Переносимый
llama.cpp b11125, CPU, 4 потока, контекст 4096, один запрос одновременно,
thinking отключён. Сервер слушает только `127.0.0.1:8082`.
Скрипт использует Python из виртуального окружения первого модуля;
дополнительные pip-пакеты не нужны. Для повторной установки требуется Python 3.11+:

```powershell
..\01_Speech_Transcription_Module\.venv\Scripts\python.exe .\setup_model.py
.\start_server.ps1 -Background
```

Сервер остаётся запущенным для следующих запросов. Логи и PID находятся в `logs`.
Для остановки проверьте процесс по PID из `logs/server.pid` и завершите именно
этот `llama-server.exe` через диспетчер задач. Исходники, модель и runtime находятся
в этой папке; глобальная установка и изменения PATH не требуются.

## Границы достоверности

Это предварительные текстовые гипотезы, не акустическая диаризация и не
подтверждение личности. Все метки имеют `status: needs_review`; выдуманных
процентов уверенности нет. Реплики могут быть объединены внутри ASR-сегмента;
границы вывода поэтому имеют точность исходных сегментов. Имена участников не
присваиваются. Указанный тип относится к локальному фрагменту: внутри общего
полилога возможны монологические доклады.

Длинные записи анализируются порциями с двумя предыдущими сегментами контекста.
На границах порций фрагменты могут быть разделены. Программа проверяет полное
покрытие входных сегментов без пропусков/пересечений и точность цитат, но эти проверки
не доказывают правильность смысловой классификации. При неточной цитате фрагмент
помечается `uncertain`, цитата удаляется, причина записывается в `review_reason`.
При пропущенных или пересекающихся диапазонах программа завершается с ошибкой
и не сохраняет результат этого файла. Уже сохранённые результаты
других файлов остаются. Чрезмерно длинный одиночный сегмент нужно предварительно разделить.
